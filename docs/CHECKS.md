## Exact-source test proof

Run with non-optimized Python after source, SQL, locks, fixtures, tests, and release tooling are frozen:

```powershell
.\.venv\Scripts\python.exe scripts\run_tests.py -q
```

Default outputs are `artifacts/checks/full-suite.xml` and `full-suite.source-proof.json`. The proof records the actual XML counts, skips, failures, errors, child exit status, platform/Python, and file hashes before and after execution. A changed, missing, added, selected, empty, skipped, failed, stale, or optimized run cannot pass the release gate. Old result files are copied to `artifacts/checks/history/` before a new invocation; they are historical evidence, not the current run.

On Linux, run the same checked-out bytes:

```sh
.venv/bin/python scripts/run_tests.py -q --junitxml artifacts/checks/linux-full-suite.xml
```

Copy the Linux XML and its matching `linux-full-suite.source-proof.json` back unchanged. The manifest requires current-source Windows and Linux full-suite proofs, equal actual test counts, zero failures/errors/skips, and assertions enabled. It does not substitute an earlier prototype or infer a successful run from a workflow file. `PYTEST_ADDOPTS` is rejected; explicit selection/plugin/file arguments are not accepted as proof of the complete default suite.

The existing destination-guarded harnesses can be run with the same byte binding:

```powershell
.\.venv\Scripts\python.exe scripts\run_tests.py --harness acceptance
.\.venv\Scripts\python.exe scripts\run_tests.py --harness recovery
.\.venv\Scripts\python.exe scripts\run_tests.py --harness backup
```

These preserve existing harness behavior. They do not reset serving data. The manifest requires 89 independent fixture-oracle checks, 17 real process-recovery checks, and the 23-table restore/14-replay/zero-additional-effect oracle, with each matching current-source proof. Whole-pytest counts remain dynamic and separate from these denominators.

## Security scope

The raw npm report must also report zero vulnerabilities. The official and hardened all-extras Airflow constraint inventories remain separate, including their recorded optional-package advisories; their findings are never silently discarded.

`source-exposure.json` must contain zero findings. Static analysis must retain the raw findings and reviewed dispositions, have no high findings or undefined names, and have no unreviewed medium call sites. The root auditor must refresh these reports after release-tool changes. An artifact hash binds bytes and preserves its scan time/scope; it does not invent a new scanner execution.

Pass an actual OS report with `--os-report`. A missing, blocked, or unverified OS scan is recorded explicitly with `findings: null`, not fabricated zero. Package matching is not an OS scan. Remote CI likewise remains blocked/unverified until an actual successful GitHub Actions run URL/ID/conclusion is supplied with `--ci-report`; a configured workflow is not green CI.

## Benchmarks

Final benchmark summaries must be explicitly selected together:

```powershell
.\.venv\Scripts\python.exe scripts\release_manifest.py --small-benchmark artifacts/benchmarks/FINAL-SMALL.json --large-benchmark artifacts/benchmarks/FINAL-LARGE.json
```

Replace these placeholder names with the actual verified summary paths. The small summary must contain all six one/four-worker repetitions and pass independent reconciliation. The large merged summary must bind six actual report files, six distinct declared trial VMs, the exact passing small-gate hash, current core/SQL, current harness/wrapper, inputs, and raw evidence. Every selected raw file is size/hash checked, and gzip contents are fully decompressed to validate integrity. Failed/interrupted/partial trials do not become successful measurements.

The manifest recomputes per-worker throughput medians from the actual trial values and retains individual p95 values rather than averaging them into a false pooled percentile. The recorded latency definition and microVM/topology limitations remain visible. These are synthetic HTTP/core-worker measurements; pipeline/dbt capacity, hosted service SLOs, and causal same-host speedup claims are excluded.

With no explicit final pair, benchmark status is `not_verified` and metrics are absent. Older benchmark JSON files are listed as historical/prototype evidence and are not promoted because they happen to be present or faster.

## Generate and package

Generate the manifest after current evidence and audit refresh. `--check-only` performs the same checks without writing a manifest. Missing or failed mandatory evidence produces a failed gate and a nonzero exit; it is not repaired by filling in invented results.

The owner then reviews and commits all release inputs. Only after that commit:

```powershell
.\.venv\Scripts\python.exe scripts\package_release.py
```

The packager requires a passing current manifest, clean tracked state, and exact Git-HEAD bytes for every protected input. It archives **Git HEAD**, then adds only explicitly bound evidence (including selected ignored raw benchmark gzip files), the recorded `outputs/OrderFlow_Demo.mp4`, and the final viewport preview. It rejects private/runtime paths, unsafe ZIP names, symlinks, duplicate members, stale bytes, and content changes during packaging.

Outputs are `OrderFlow_Complete.zip`, `OrderFlow_Preview.png`, `OrderFlow_Checksums.json`, and `OrderFlow_Verification.json` alongside the selected demo. Internal content hashes deliberately exclude their own verification file; the external report additionally binds the finished archive. No script commits, pushes, publishes, upgrades dependencies, or resets serving data.

The resume and career pack remain separate deliverables. Packaging must preserve the existing `Portfolio_Resume.pdf` byte hash and frozen ResolveLab v0.2 artifacts. Source visibility, hosted runtime/Neon terms, and external publication remain owner decisions.
