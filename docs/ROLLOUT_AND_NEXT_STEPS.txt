ORDERFLOW: CURRENT DELIVERY AND FOLLOW-UP

Current deployment

The stable app is https://orderflow-hazel.vercel.app, deployed through the public
GitHub repository's approved main-to-Vercel connection. FastAPI, Neon PostgreSQL,
Managed Better Auth, immutable PostgreSQL objects and private finite Queue phases
are implemented on the existing free-plan setup. Fixture authentication is off in
production. docs/PRODUCTION.md identifies the executed hosted checks and limits.

Earlier marketplace terms, missing-hosting and GitHub-runner restrictions describe
historical checkpoints. They are not current account or billing blockers. Public
source and actual CI/deployment results supersede the old rollout checklist.

Handbook addition

docs/CUSTOMER_MAPPING.md documents one synthetic noncanonical merchant export,
exact money/time/identity mapping, source authority, actual acceptance results
and operator handoff through the existing paginated connector. The local/offline
example adds no public API, cloud, schema, customer integration or paid service.
It is automated simulation, not human/customer acceptance or business savings.

The independent v2 Linux core benchmark has now completed; the original failed
v1 matrix remains not_verified. analysis/README.md and the versioned review give
separate source pins, raw evidence, latency/backlog caveats and denominators.

Security and operating follow-up

- The optional local/Linux Airflow environment's SMTP provider pin is patched
  from 3.2.0 to 3.2.2 for PYSEC-2026-4396. Inspect the versioned review and actual
  final CI installation/DAG results; resolved metadata alone is not installation.
- Monitor existing storage, database connections, queue age, failed jobs and
  email/execution quotas. Hosted objects have limits and no implicit purge.
- Retain failed attempts and last-good publication; use reviewed ownership,
  cursor and new-identity/version correction rules rather than deleting history.
- Name a human acceptance/incident owner and review source authority, retention,
  rate limits and credential rotation before a real merchant pilot.
- Establish traffic-derived SLOs and a separately tested backup schedule only
  when actually adopted. Application-schema recovery is not full-account recovery.
- Keep historic OS/container advisory findings scoped to their original image
  snapshots; app dependency scans do not audit the managed Vercel host OS.
- Human screen-reader/operator acceptance and merchant adoption remain unmeasured.

No billing upgrade, extra cloud, AWS service or always-on scheduler is required
by this handbook update. Preserve the existing free-tier architecture and quotas.
