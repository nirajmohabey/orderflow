# OrderFlow v0.1.1 native review

The patch review is separate from the frozen v0.1.0 release gate. The current
collector is `scripts/review_patch.py`; it writes
`artifacts/recheck-2026-11-23/review-manifest-v0.1.1.json`. It requires a complete
current Windows suite with zero failures, errors and skips, the independent
89-check acceptance and 17-check process-recovery proofs, and a separate restored
copy with 23 matching tables, 14 duplicate replays, zero new worker effects, and
observed restore-database/private-dump cleanup. Test counts come from the actual
source-bound JUnit proof rather than a copied historical count.

After source edits finish, the native evidence commands are:

```powershell
.venv/Scripts/python.exe scripts/run_tests.py --label recheck-native --junitxml artifacts/recheck-2026-11-23/native/full-suite.xml -q
.venv/Scripts/python.exe scripts/run_tests.py --label recheck-native --harness acceptance --harness-output artifacts/recheck-2026-11-23/native/acceptance.json
.venv/Scripts/python.exe scripts/run_tests.py --label recheck-native --harness recovery --harness-output artifacts/recheck-2026-11-23/native/recovery.json
.venv/Scripts/python.exe scripts/run_tests.py --label recheck-native --harness backup --harness-output artifacts/recheck-2026-11-23/native/backup-restore.json
```

These guarded verifiers use their configured disposable test destinations or
newly owned verification databases. Their matching `.source-proof.json` files
must identify the unchanged current source, SQL, fixtures, dependencies,
verification tools and frontend. They must not reset the configured serving
workspace.

After current dependency/security evidence and final UI proofs are available:

```powershell
.venv/Scripts/python.exe scripts/review_patch.py --ui-work-dir ../../work/recheck-orderflow/v0.1.1
.venv/Scripts/python.exe scripts/review_patch.py --verify
```

The UI directory supplies 18 existing intercepted scenarios, 5 new intercepted
regressions, 10 real HTTP/PostgreSQL journeys,25/22 recorded accessibility states,
pre/post source and report hashes, and observed serving-state preservation and
owned-runtime cleanup. These denominators remain separate. Supplemental DOM,
visual and accessibility triage may be attached as additional hashed artifacts;
they do not increase the real-service journey count or establish full WCAG
conformance.

The dependency evidence distinguishes fresh native application/dbt inventories
from a historical Linux Airflow installed inventory whose exact versions were
queried again. Zero matches in the required graphs does not erase the advisory
findings retained in optional Airflow constraint inventories. Source exposure,
full static findings and the medium-finding review keep their generated times,
source snapshots and raw report hashes. Added output artifacts should receive a
final package/exposure scan before sharing.

The recorded 104-test Linux suite, original container smoke and exact-image OS
scan are historical evidence for v0.1.0. They do not validate the patched source.
The selected old OS images retained 868 advisory/package occurrences, including
200 HIGH occurrences repeated across four Python-based roles; these are not 868
unique vulnerabilities. The separate reference Debian PostgreSQL image was not
the selected PostgreSQL runtime. Current Linux, container rebuild/OS scan,
remote CI and hosted backend operation remain unverified. Free cloud execution
quota was exhausted; this review does not authorize a paid upgrade.

The original v1 benchmark is retained with its failed report and raw evidence:
10k passed 6/6 trials;100k passed 5/6 and failed one API postflight. Its missing
contemporaneous HTTP statuses are not reconstructed. The source/timing expiry
diagnosis and separate focused HTTP reproduction do not turn that trial into a
pass. Its benchmark status remains `not_verified`, and the retained timings are
historical partial observations rather than current-source performance claims.

The future v2 harness received bounded fixes: idle full-scan catch-up prevents
an older transaction marker from blocking the drain signal forever, and 100k
admission checks all six source-bound 10k trial records, fresh postflight checks
and raw file hashes/CRC. Resume also retains the selected small-gate binding.
Thirteen CPU/mocked regression cases exercise these boundaries. They do not run
or establish a new 10k/100k performance matrix.

The original strict release builder, partial renderer/binder and package helper
remain scoped to v0.1.0. They correctly reject changed source or cannot be used
to label an unavailable current Linux run as passed. Use the new patch manifest
for current native evidence, preserve older reports as historical, and use
freshly bound UI media when assembling v0.1.1 deliverables.
