# OrderFlow deterministic fixtures

These are synthetic design fixtures for the service you will implement. They contain no credentials or live customer data. Implement a loader that seeds `seed_metadata.json`, posts each record's `envelope` to `/v1/sources/{source_id}/events`, and waits for terminal processing before comparing with `expected_state.json`.

Replay the files in the order specified by the oracle. The `source_id` wrapper is loader metadata and is not part of the HTTP body. Duplicates reuse the complete original envelope. `late_versions.jsonl` deliberately submits product version 3 before version 2. `equal_effective_times.jsonl` adds two revisions of P2 with the same effective timestamp; keep both raw revisions and select only version 2 before deriving curated history intervals. The equal-version conflict and the tenant-currency mismatch pass the basic JSON shape check but must be quarantined by materialization rules. Tenant two reuses a source event name and entity name without sharing its data.

The final tenant-one counts are 10 accepted inbox identities, 10 terminal receipts, 8 raw entity revisions, 2 current products, 2 current orders and 2 terminal quarantines. They exclude repeated submissions of identical source event IDs. Order amounts are latest snapshots, not additive events: O1 version 2 is 3,000 cents and O2 version 1 is 5,000 cents, totaling 8,000 cents. Both latest orders are paid. Product history uses half-open intervals and includes a late inserted middle revision and the collapsed equal-time P2 revision. Do not compute expected values by calling the production materializer.

The CSV is a separate inventory reconciliation input. It does not claim that the product or order event schema supports inventory entities. Compare `inventory_snapshot.csv` with the explicitly synthetic `inventory_reference.csv`: SKU-1 is 20 observed units versus 22 reference units, giving a difference of -2 and a failed check. The blueprint specifies raw snapshot and report artifact paths. Monetary order totals are not an inventory reference. An administrator seeds and authorizes the source; the adapter derives stable identities when replaying the file.

For recovery tests, choose a known event and inject a failure inside the database transaction. Restart processing and compare against the same oracle. For HTTP rejection tests, make a copy of a fixture in the test itself and remove a required field; assert 422 and no accepted inbox record.
